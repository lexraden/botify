# CLAUDE.md — как работать с Claude Code в этом проекте

Основано на гайде Anthropic «Maximizing the value of your Claude Code sessions».
Цель — тратить токены только на то, что реально нужно для задачи, а не на лишний
контекст, который тянется через всю сессию.

## Главные правила (следовать по умолчанию)

1. **`/clear` между разными задачами.** Если закончил с оплатой и переходишь к
   загрузке фото товаров — `/clear`, не продолжай в том же чате. Старый контекст
   (файлы, которые уже не нужны) иначе тянется в каждый следующий запрос и
   раздувает счёт.

2. **`/compact` перед перерывом.** Если уходишь из-за компьютера (обед, сон,
   дела) — сначала `/compact`, а не просто закрывай терминал. Кэш промпта живёт
   около часа, и сжатие разговора дешевле сделать, пока кэш ещё жив, чем потом
   с нуля.

3. **Упоминай файлы через `@путь/к/файлу`**, а не просто называй их текстом.
   Например: «поправь `@backend/app/payments/payouts.py`» — файл сразу
   прикрепляется к сообщению, экономит отдельный вызов на чтение файла.
   Упоминать один и тот же файл дважды за сессию не нужно — он и так остаётся
   в контексте.

4. **Не переключай модель/effort level в середине разговора.** Если решил
   сменить модель — делай это в начале новой сессии (после `/clear`), а не
   посреди работы. Переключение сбрасывает кэш, и весь разговор пересчитывается
   заново по полной цене.

5. **`/rewind` вместо `/compact`, если просто нужно отменить последние шаги.**
   Если Claude Code пошёл не туда в последних 2–3 действиях — `/rewind`
   откатывает именно их, не трогая остальной кэшированный разговор. Это
   бесплатно. `/compact` — платно, потому что переписывает весь разговор.

## Специфично для этого проекта

- **Один блок задач = одна сессия.** Не смешивай в одной сессии «протестить
  оплату» и «разобраться с фото товаров» — это разные куски кода
  (payments/webhook vs upload/storage), `/clear` между ними.
- **Тестирование = отдельная сессия от разработки.** Когда просишь погонять
  тесты/логи (много вывода в консоль) — если вывод большой и не нужен целиком
  в истории, попроси сделать это через subagent («прогони тесты в саб-агенте»),
  тогда в основной разговор вернётся только итог, а не все 400 строк лога.
- **Шумные команды — с тихими флагами** (см. блок «Команды» ниже, там они уже
  зафиксированы).
- **`/context` в начале свежей сессии** — раз в какое-то время проверять, что
  вообще загружено (CLAUDE.md, MCP-инструменты), и выключать через `/mcp` то,
  что не нужно именно сегодня.

### Чеклист на каждый день разработки

- [ ] Перед стартом: `/model` и `/effort` — проверить, что стоит нужное
      (тяжёлая модель для архитектурных решений вроде мультибот-раннера,
      лёгкая — для рутины вроде правок текста)
- [ ] Одна логическая задача — одна сессия, `/clear` между ними
- [ ] Файлы — через `@путь`, не текстом
- [ ] Перед уходом от компьютера — `/compact`
- [ ] Если что-то пошло не туда — `/rewind`, не `/compact`

## Команды проекта (тихие варианты)

Запускать именно в таком виде — они не забивают контекст выводом.

```bash
# Тесты (в песочнице Postgres нужно поднять руками)
service postgresql start
cd backend && .venv/bin/python -m pytest -q

# Один файл/тест
cd backend && .venv/bin/python -m pytest -q tests/test_fulfillment.py

# Сборка витрины после правок во webapp (dist коммитится в репозиторий)
cd webapp && npm run build 2>&1 | tail -5

# Миграции: применить
cd backend && .venv/bin/python -m alembic upgrade head

# Локальный запуск бэкенда (без WEBHOOK_BASE_URL вебхуки не регистрируются)
cd backend && .venv/bin/uvicorn app.main:app --port 8088
```

Тестовая БД по умолчанию — `postgresql+asyncpg://botify:botify@localhost:5432/botify_test`
(переопределяется `TEST_DATABASE_URL`); схема поднимается через `create_all`,
alembic там не прогоняется.

**Проверка миграции перед пушем** — на отдельной пустой базе, а не на тестовой,
и обязательно в обе стороны:

```bash
su postgres -c "psql -c 'DROP DATABASE IF EXISTS botify_mig' -c 'CREATE DATABASE botify_mig OWNER botify'"
cd backend && DATABASE_URL=postgresql+asyncpg://botify:botify@localhost:5432/botify_mig \
  .venv/bin/python -m alembic upgrade head && \
  .venv/bin/python -m alembic downgrade -1 && \
  .venv/bin/python -m alembic upgrade head
```

## Что нужно знать про код

- Архитектура и решения: `docs/AUDIT.md`, бриф: `docs/project-brief.md`,
  краткая карта репозитория: `README.md`.
- **Один подключённый бот = один изолированный магазин.** Каталог, покупатели,
  заказы, рассылки и статистика фильтруются по `bot_id`, а не по продавцу.
  Любой новый ресурс магазина заводится с `bot_id` и живёт под
  `/api/seller/bots/{bot_id}/…`.
- **Токены seller-ботов не хранятся в открытом виде** — только Fernet
  (`app/security.py`). В логи и ответы API они не попадают.
- **Схема БД меняется только миграцией.** Alembic-autogenerate тут не
  используется (нужна живая БД с историей) — миграции пишутся руками, с
  `downgrade` и, если надо, с бэкфиллом данных.
- **Выплаты копятся, а не уходят по заказу** (`app/payments/payouts.py`):
  у Crypto Pay свой минимум на transfer, ниже него — `AMOUNT_TOO_SMALL`.
  Порог — `MIN_PAYOUT_USDT`.
- Тексты бота и Mini App — на «ты», по-русски.

## Ограничения окружения

- Прод-домен Railway из песочницы недоступен (прокси отвечает 403), так что
  проверить деплой можно только руками на стороне владельца проекта — не
  выдавать «проверено», если проверки не было.
- Разработка идёт в ветке `claude/chat-session-*`, PR создаётся только по
  явной просьбе.

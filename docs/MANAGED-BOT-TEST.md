# Managed bot: как прогнать сценарий живьём

Ветка `managed-bot-case`. Проверяем одно: можно ли создать бота продавца
**кнопкой внутри нашего hub-бота**, без BotFather и без копипаста токена.

Из среды разработки это не проверить — Telegram оттуда недоступен. Всё, что
можно было проверить локально, проверено тестами
(`backend/tests/test_managed_bot_onboarding.py`, 19 штук). Остаётся живой прогон.

---

## Что происходит по шагам

1. `/newshop` в hub-боте → бот спрашивает название магазина.
2. Название сохраняется как **черновик** — строка `seller_bots` с пустым
   токеном и `is_active = false`. `bot_id` есть уже здесь.
3. В ответ приходит reply-кнопка `KeyboardButtonRequestManagedBot` с
   `suggested_name` (название) и `suggested_username` (транслит из названия).
4. Продавец жмёт кнопку → **Telegram сам** показывает диалог создания бота и
   сам проверяет занятость адреса.
5. Нам приходит сообщение с `managed_bot_created` → берём токен через
   `getManagedBotToken(user_id)` → дописываем черновик → ставим вебхук.

Владелец созданного бота — продавец. Мы только управляющий бот: в
`ManagedBotUpdated.user` Telegram присылает «User that created the bot», а в
`BotAccessSettings` записано «The bot's owner can always access it».

---

## Перед прогоном

**Деплой должен собираться с ветки `managed-bot-case`**, иначе ничего из этого
в проде не окажется.

Миграция `n9f0a1b2c3d4` делает токен, юзернейм и `telegram_bot_id` в
`seller_bots` необязательными и добавляет `title`. Существующим магазинам
`title` проставляется юзернеймом бота. Проверено на базе с данными в обе
стороны; `downgrade` **удаляет черновики** — иначе NOT NULL не встанет обратно.

Вебхук hub-бота теперь ставится с явным `allowed_updates`
(`app/bots/hub.py:HUB_ALLOWED_UPDATES`), потому что `managed_bot` в
дефолтную выдачу Telegram не входит. Список применяется при старте приложения —
после деплоя он переустановится сам.

## Прогон

- [ ] `/newshop` → бот просит название
- [ ] Отправить «Кофейня у дома» → приходит кнопка с подписью
      «🤖 Создать бота «Кофейня у дома»» и предложенным адресом
      `@kofeynya_u_doma_bot`
- [ ] **Нажать кнопку — вот здесь и выяснится главное.** Telegram должен
      показать свой диалог создания бота с подставленными именем и адресом
- [ ] Подтвердить создание → приходит «✅ Магазин подключён к @…»
- [ ] `/mybots` → магазин в списке, зелёный
- [ ] Написать созданному боту `/start` → отвечает приветствием (значит вебхук
      встал и токен рабочий)
- [ ] Открыть Mini App, добавить товар, открыть витрину

### Что смотреть, если пошло не так

| Симптом | Где смотреть |
|---|---|
| Кнопка не появилась | логи, `got_title` — создался ли черновик |
| Нажатие ничего не делает | `managed_bot` не в `allowed_updates` вебхука, либо метод недоступен аккаунту |
| «Бот создан, но забрать его токен не вышло» | `getManagedBotToken` вернул ошибку — её текст в логах |
| Бот создан, но `/start` молчит | вебхук не встал: `setup_seller_webhook` вернул False |

## Что выяснить попутно

Это те вопросы, на которые у меня нет ответа из кода:

1. **Виден ли созданный бот в `/mybots` у BotFather.** Если да — продавец может
   там перевыпустить токен и уронить наш вебхук. Детекция у нас есть
   (`bot_health` ловит 401), а чинить можно через `replaceManagedBotToken`
   вместо переподключения.
2. **Считаются ли managed-боты в лимит ботов на аккаунт.**
3. **Кому это вообще доступно** — всем аккаунтам или нет.
4. **Что приходит в апдейте `managed_bot`** при смене токена и владельца.
   Сейчас хендлер только пишет в лог (`newshop.py:managed_bot_changed`) —
   посмотреть логи после прогона и решить, как реагировать.

---

## Чего в этой ветке намеренно нет

- **Mini App не тронут.** Сценарий живёт целиком в hub-боте, чтобы проверялась
  механика, а не вёрстка. Если механика работает — экран названия магазина в
  приложении будет обёрткой поверх этого же кода.
- **Ручной ввод токена оставлен как был** (`POST /api/seller/bots`). У
  существующих продавцов боты уже созданы через BotFather, и managed-боты
  могут оказаться доступны не всем.
- **Товары до бота** не переносил. С кнопкой вместо BotFather тяжёлый шаг
  перестаёт быть тяжёлым, и заводить товары в магазин без витрины смысла мало
  — но черновик это уже позволяет, если решим иначе.

# Changelog

## 2026-08-24 (2) — ревью ox-alpha: адреса картинок и проверка на масштаб

### Fixed
- Адрес фото товара был порядковым id, а картинка отдаётся с `Cache-Control: immutable` на год. После сброса базы нумерация начиналась заново, и браузер показывал из кэша старую картинку по совпавшему адресу. Теперь адрес — случайный токен (`product_images.token`, миграция `a7b8c9d0e1f2`), переиспользоваться он не может; миграция переписывает и `products.image_url` у уже загруженных фото.

### Changed
- Индекс на `orders.paid_at`: оборот за 30 дней в `/health` был единственным запросом, сканирующим таблицу заказов целиком. На 100 тыс. заказов 26 мс → 10 мс, дальше разница растёт линейно.

### Removed
- Из репозитория убран случайно закоммиченный `backend/botify_test.db` (294 КБ, тестовый прогон на SQLite; секретов не содержал). В `.gitignore` добавлены `*.db` и `*.sqlite3`.

## 2026-08-24 (5) — случайный spend_id пачек выплат

### Fixed
- SPEND_ID_ALREADY_USED после сброса базы: spend_id перевода раньше вычислялся
  как `batch-{id}` — нумерация пачек начиналась заново, и Crypto Pay отбивал
  перевод уже занятым ключом. Теперь у `payout_batches` есть колонка `spend_id`
  со случайным токеном (`secrets.token_urlsafe(16)`), генерируется один раз при
  создании пачки и не меняется при повторных попытках отправить её —
  идемпотентность ретраев сохранена.

### Added
- Миграция `f9e8d7c6b5a4`: колонка + бэкфилл существующих строк значением
  `batch-{id}` (исторические spend_id не меняются), NOT NULL и unique;
  downgrade пересоздаёт таблицу без колонки (нативный DROP COLUMN на SQLite
  запрещён для столбца с UNIQUE). Проверена на SQLite в обе стороны,
  бэкфилл подтверждён.
- Тест: transfer шлёт ровно сохранённый в пачке токен, у новых пачек токены
  разные (121 passed).
- [docs/REVIEW.md](docs/REVIEW.md) — файл для заметок следующему агенту
  (ручные действия после деплоя). Первый пункт: застрявшие пачки со старым
  spend_id нужно удалить после миграции — доли отвяжутся и уйдут новой пачкой.
  Указатель на файл добавлен в CLAUDE.md.

### Changed
- README: этап 6 описывает выплаты только по кнопке «Вывести» с токеном-идемпотентностью.

## 2026-08-24 (4) — кошелёк: подключение оплаты, автоматика выплат убрана

### Changed
- Блок «Баланс магазина»: пока оплата не подключена, вместо неактивной кнопки
  «Вывести» — активная зелёная «Подключить оплату» (открывает @CryptoBot)
  с инструкцией («нажми /start, вернись и подтверди») и кнопкой
  «Готово, я нажал /start». После подключения — обычная «Вывести», неактивная
  при балансе ноль или ниже минимума. Пока данные продавца грузятся, ни одна
  из веток не показывается (не мигает).
- Убрано задвоение строки статуса («Здесь копятся деньги с продаж» и др.) —
  она выводится один раз над любым вариантом блока. Пересобран `webapp/dist`.

### Removed
- Вся автоматика выплат — деньги уходят только по запросу продавца:
  ежечасный цикл ретрая (`payout_retry_loop` / `process_unsent_payouts`),
  авто-выплата после оплаты digital-заказа и авто-выплата после fulfillment.
  Тексты продавцу переписаны без обещания «повторим автоматически» — теперь
  «нажми „Вывести“ ещё раз, когда проблема уйдёт». Упавшая пачка при следующем
  нажатии уходит с тем же идемпотентным ключом. Новый тест: оплаченный заказ
  сам не запускает перевод (120 passed).

## 2026-08-24 (3) — онбординг из одного шага, оплата переехала в кошелёк

### Changed
- Онбординг сжат до единственного шага — подключение бота через @BotFather:
  индикаторы прогресса убраны, описание шага — «Через него покупатели будут
  заходить в твой магазин и получать рассылки». После подключения первого
  магазина — экран поздравления «Магазин создан!» с кнопкой «Далее»
  (`OnboardingDone.vue`, маршрут `/onboarding/done`). Повторное подключение
  (второй магазин) ведёт прямо в магазин, без поздравления.
- Шаг подключения оплаты переехал из онбординга в кабинет: в блоке
  «Баланс магазина» вкладки «Статистика». Вывод средств стал prerequisite:
  сервер отвергает `POST /payouts/withdraw` с `reason=payment_not_connected`,
  пока продавец не нажал /start у @CryptoBot. Дефолт `onboarding_step`
  сменён на `bot_pending` на стороне ORM (значение `payment_pending`
  остаётся legacy у старых строк; серверный DEFAULT не трогали).
- Точка входа Mini App (`entryRouteFor`): без ботов — сперва условия,
  потом шаг бота; один активный бот — сразу в магазин. Пересобран `webapp/dist`.

### Removed
- Экран онбординг-оплаты (`OnboardingPayment.vue`) и механизм intro-экранов
  (`services/intro.js`), маршруты `/onboarding/payment` и `/intro`.

## 2026-08-22 (8) — ревью ветки ox-alpha
